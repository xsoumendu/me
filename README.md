# Github Page | Astro framework | Javascript/Typescript rendering

A single-page professional resume for Soumendu Nandi, Solution Architect and product engineer. It presents experience, technical capabilities, selected engagements, credentials, and contact details as a focused, responsive web experience.

> A good architecture makes the important things easy and the impossible things obvious. This site applies the same rule to a resume: one source of truth, clear boundaries, and no meetings required to load a page.

## Architecture

The site is intentionally small and static-first:

- `src/pages/index.astro` is the composition root. It assembles each resume section inside the shared document layout.
- `src/layouts/Layout.astro` owns document metadata, the favicon, global design tokens, typography, and shared responsive rules.
- `src/components/` contains independently styled presentation sections: hero, experience timeline, skills, engagements, and contact.
- `src/data/resume.ts` is the content model and single source of truth for profile details, employment history, skills, projects, education, and certifications.
- `public/` holds directly served assets such as the profile image and downloadable PDF resume.

> Data belongs in a model, layout belongs in a layout, and a component should have fewer responsibilities than an architect's Monday morning calendar.

## Dependencies

The production dependency graph is deliberately short:

| Package | Role |
| --- | --- |
| `astro` | Builds, serves, and previews the resume site. |

There are no React, Vue, Svelte, CSS framework, icon, analytics, or client-side state dependencies. That is an intentional performance decision: a resume should introduce its author before it introduces a JavaScript bundle.

## Local Development

Prerequisite: a current Node.js LTS release and npm.

```bash
npm install
npm run dev
```

Use the local URL printed by Astro. The remaining commands are:

```bash
npm run build    # Produce the deployable static site in dist/
npm run preview  # Serve the built site locally
```

## GitHub Pages Deployment

GitHub Pages serves the static files generated by Astro; it does not run the Astro development server. This repository deploys through [`.github/workflows/astro.yml`](.github/workflows/astro.yml): every push to `main`, or a manual workflow run, builds and publishes the site.

1. GitHub Actions checks out the repository, restores the npm cache, and runs `npm ci` from the lockfile.
2. The workflow invokes `astro build` with `SITE_URL=https://xsoumendu.github.io` and `BASE_PATH=/me`.
3. Astro renders the `.astro` components and TypeScript resume data into static HTML, CSS, and assets in `dist/`.
4. The workflow uploads `dist/` as a Pages artifact and `actions/deploy-pages` publishes it.

The configured base path means the deployed site lives at `https://xsoumendu.github.io/me/`, rather than the domain root. `Layout.astro`, `Hero.astro`, and `Contact.astro` use `import.meta.env.BASE_URL` when linking the favicon, profile image, and PDF, so Astro writes `/me/`-prefixed asset paths during the Pages build. This keeps direct asset requests from accidentally knocking on the wrong front door.

In the repository's GitHub settings, set **Pages** to use **GitHub Actions** as the build and deployment source. The workflow has the `contents: read`, `pages: write`, and `id-token: write` permissions required to publish.

> GitHub Pages is the plot of land; Astro is the construction crew; `dist/` is the finished building handed over at the gate.

## Use as a Template

1. Select **Use this template** on GitHub when the repository has been marked as a template, or fork/clone it into your own repository.
2. Run `npm install` and `npm run dev` to start a local copy.
3. Replace the content in `src/data/resume.ts` and the personal assets in `public/`. Keep the file names `profile.jpeg` and `resume.pdf`, or update each reference in `Hero.astro` and `Contact.astro` after renaming them.
4. Update the default title and description in `src/layouts/Layout.astro`, then revise the navigation and section headings in `src/pages/index.astro` or individual components to suit your story.
5. For GitHub Pages, change `SITE_URL` and `BASE_PATH` in `.github/workflows/astro.yml`. A repository named `your-name.github.io` deploys at the domain root and can use `/` as its base; a project repository named `portfolio` should use `/portfolio`.
6. Run `npm run build` before pushing to confirm the static site compiles. After the first push to `main`, enable **GitHub Actions** under the repository's Pages settings.

The license permits reuse, but the supplied personal profile, contact details, photograph, and PDF are not a starting kit. Replace them before publishing your version.

## Updating Content

Edit `src/data/resume.ts` to update resume content. The section components render that data through arrays and maps, so adding a skill, role, engagement, credential, or summary item does not require changing the page structure.

For visual changes, use the component-local `<style>` blocks for section-specific rules and `src/layouts/Layout.astro` for global tokens and shared styles.

> The best content management system is sometimes a typed file with one job and no committee.

## Changing the Color Theme

The global palette lives in the `:root` block of `src/layouts/Layout.astro`. Update these CSS variables to establish a new theme while preserving the existing layout:

```css
:root {
	--ink: #14211f;     /* primary text and dark surfaces */
	--muted: #53605c;   /* supporting text */
	--paper: #f4f0e8;   /* page background */
	--surface: #fffdf8; /* light section background */
	--line: #d9d5ca;    /* borders and the hero grid */
	--teal: #0a7168;    /* primary accent */
	--coral: #e76252;   /* secondary accent */
	--lime: #c8d94d;    /* highlight accent */
}
```

The variables are used across sections for text, buttons, borders, and backgrounds. A few section-specific shades are written directly in `Skills.astro`, `Projects.astro`, and `Contact.astro`; revise those alongside the variables when changing the palette. Build and inspect the site afterward to confirm text and button contrast remains readable.

## Theme and Template

This is a bespoke Astro resume theme, not an installed or forked starter template. The visual system is defined in the repository:

- `src/layouts/Layout.astro` establishes the paper, ink, teal, coral, and lime design tokens plus the shared typography and layout rules.
- Each section component owns its responsive layout and scoped styles, including the grid-textured hero, timeline, capability grid, and engagement list.
- The theme uses semantic HTML and CSS only; it does not depend on a component library, CSS framework, icon pack, or JavaScript animation framework.

> The theme has no mystery box dependency: the blueprint, materials, and load-bearing CSS are all on site.
